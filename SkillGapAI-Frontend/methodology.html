📑 Text Preprocessing Pipeline

In technical resume and job description analysis, conventional naive tokenization routines fail dramatically. Standard word-boundary regular expressions (e.g., \w+ or \bword\b) destroy critical programming language identifiers such as C++, C#, .NET, Node.js, and CI/CD, stripping non-word symbols and converting C++ into c, which then collides with common stopwords or abbreviations.

1. Symbol-Preserving Token Mapping

SkillGap AI addresses this through a two-phase tokenization strategy:

  • Protection Phase: High-risk technical patterns are identified via fixed-width lookaround regular expressions and mapped to unique alphanumeric placeholders (e.g., c++ $\to$ __TECH_CPP__).
  • Standard Processing Phase: Lowercasing, whitespace normalization, and boundary tokenization execute safely without symbol corruption.
  • Restoration Phase: Encoded placeholders are restored back to canonical display strings, preserving exact character spans for downstream highlight mapping.

2. Morphological Normalization: Stemming vs. Lemmatization

The pipeline implements both algorithmic suffix stripping (Porter Stemmer) and morphological dictionary lookup (WordNet Lemmatizer):

$$\text{Stemming (Porter):} \quad \text{developments} \to \text{develop}, \quad \text{organizing} \to \text{organ}$$ $$\text{Lemmatization (WordNet):} \quad \text{developments} \xrightarrow{\text{noun}} \text{development}, \quad \text{ran} \xrightarrow{\text{verb}} \text{run}$$

Crucial Academic Rule: Neither stemming nor aggressive stopword removal is applied to canonical skill entities. For example, "Go" is preserved as a programming language rather than being discarded as an imperative verb.

📐 Bag-of-Words & TF-IDF Cosine Similarity

The lexical matching engine constructs vector space representations for candidate resumes ($D_{\text{res}}$) and job descriptions ($D_{\text{jd}}$).

1. Term Frequency & Inverse Document Frequency

To dampen the influence of repeated words in long resumes, sublinear term frequency scaling is applied:

$$\text{TF}(t, d) = \begin{cases} 1 + \log(\text{count}(t, d)) & \text{if } \text{count}(t, d) > 0 \\ 0 & \text{otherwise} \end{cases}$$

Inverse Document Frequency (IDF) smooths document frequency over the combined corpus:

$$\text{IDF}(t) = \log\left(\frac{1 + N}{1 + \text{DF}(t)}\right) + 1$$

2. Cosine Similarity in High-Dimensional Space

The similarity between resume vector $\mathbf{A} \in \mathbb{R}^V$ and job description vector $\mathbf{B} \in \mathbb{R}^V$ is defined as the cosine of the angle between them:

$$\cos(\mathbf{A}, \mathbf{B}) = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\|_2 \times \|\mathbf{B}\|_2} = \frac{\sum_{i=1}^V A_i B_i}{\sqrt{\sum_{i=1}^V A_i^2} \sqrt{\sum_{i=1}^V B_i^2}}$$

3. Document Similarity vs. Skill Coverage Distinction

Fundamental Academic Principle: Document cosine similarity measures lexical vocabulary overlap, whereas Skill Gap Analysis requires measuring requirement coverage. A resume with 90% cosine similarity might still lack the single mandatory skill required for the job. SkillGap AI strictly separates:

  • Lexical Document Similarity ($\cos(\mathbf{A}, \mathbf{B})$): Measures general stylistic, domain, and contextual phrasing alignment.
  • Skill Coverage Ratio ($|\mathcal{S}_{\text{res}} \cap \mathcal{S}_{\text{jd}}| / |\mathcal{S}_{\text{jd}}|$): Measures direct compliance against mandatory technical competencies.

🌐 Word Embeddings (Word2Vec & GloVe)

Lexical vector spaces fail when a candidate describes experience using synonymous or related terminology (e.g., "predictive analytics" vs. "machine learning"). Dense embeddings capture distributed semantic representations where words occurring in similar contexts map to proximate vectors in $\mathbb{R}^d$.

1. Word2Vec Objective Functions

SkillGap AI implements both Continuous Bag-of-Words (CBOW) and Continuous Skip-Gram:

$$\mathcal{L}_{\text{Skip-Gram}} = \sum_{t=1}^T \sum_{-c \le j \le c, j \neq 0} \log P(w_{t+j} \mid w_t)$$ $$P(w_O \mid w_I) = \frac{\exp(\mathbf{v}'_{w_O}{}^\top \mathbf{v}_{w_I})}{\sum_{w=1}^W \exp(\mathbf{v}'_w{}^\top \mathbf{v}_{w_I})}$$

With negative sampling approximation:

$$\log \sigma(\mathbf{v}'_{w_O}{}^\top \mathbf{v}_{w_I}) + \sum_{k=1}^K \mathbb{E}_{w_k \sim P_n(w)}\left[\log \sigma(-\mathbf{v}'_{w_k}{}^\top \mathbf{v}_{w_I})\right]$$

2. Vector Space Arithmetic & Analogies

Linear offsets in embedding space correspond to semantic relations, enabling vector analogy calculations:

$$\mathbf{v}_{\text{target}} = \mathbf{v}_A - \mathbf{v}_B + \mathbf{v}_C \implies \text{e.g., } \mathbf{v}_{\text{javascript}} - \mathbf{v}_{\text{web}} + \mathbf{v}_{\text{data}} \approx \mathbf{v}_{\text{python}}$$

3. Ontological Category Guardrails

A major hazard in naive semantic matching is false-positive synonymy: in unconstrained embedding space, "Python" and "Java" have very high cosine similarity (~0.82) because they occur in identical sentence contexts. However, a job requiring Java cannot be satisfied simply because a candidate knows Python. SkillGap AI introduces Ontological Category Guardrails: semantic similarity is gated by category constraints, preventing inappropriate skill substitution across divergent engineering requirements.

🤖 Transformers & Pretrained Language Models

Static word embeddings assign a single static vector to each word token regardless of its syntactic context. Pretrained Transformers resolve this through Multi-Head Self-Attention, producing contextualized token embeddings dynamically.

1. Scaled Dot-Product Self-Attention

$$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}$$ $$\text{MultiHead}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{Concat}(\text{head}_1, \dots, \text{head}_h)\mathbf{W}^O$$

2. DistilBERT Token Classification Architecture

SkillGap AI utilizes DistilBERT (6 transformer layers, 768 hidden dimension, 12 attention heads, 66M parameters), offering 97% of BERT's performance with a 60% faster inference profile suitable for CPU execution.

On top of the final transformer hidden states $\mathbf{h}_i \in \mathbb{R}^{768}$, a linear classification head computes logits over BIO entity tags:

$$\mathbf{z}_i = \mathbf{W}_{\text{ner}} \mathbf{h}_i + \mathbf{b}_{\text{ner}}, \quad \mathbf{W}_{\text{ner}} \in \mathbb{R}^{3 \times 768}, \quad \mathbf{y}_i = \text{softmax}(\mathbf{z}_i)$$

The BIO tag vocabulary comprises:

  • B-SKILL: Beginning of a technical skill entity (e.g., "PostgreSQL" in "PostgreSQL database").
  • I-SKILL: Inside continuation of a multi-token skill entity (e.g., "Learning" in "Machine Learning").
  • O: Outside any technical skill entity.

3. WordPiece Subword Tokenization & Subword Reassembly

BERT's WordPiece tokenizer fragments words into subword units with ## prefixes (e.g., flask $\to$ fl, ##ask). During fine-tuning, only the initial subword token is labeled with the entity tag, while continuation subwords receive the loss mask -100. During inference, subwords are reassembled into coherent entity strings.

⚖️ Unified Multimodal Architecture & Evaluation

1. Multimodal Score Formulation

To synthesize multiple perspectives without masking individual behaviors, the unified match score is computed as an inspectable weighted ensemble:

$$S_{\text{unified}} = w_1 S_{\text{rule}} + w_2 S_{\text{tfidf}} + w_3 S_{\text{w2v}} + w_4 S_{\text{bert}}$$ $$\text{with } w_1 = 0.25, \quad w_2 = 0.25, \quad w_3 = 0.25, \quad w_4 = 0.25, \quad \sum_{i=1}^4 w_i = 1.0$$

Each sub-score captures a distinct semantic layer:

  • $S_{\text{rule}}$: Precision-oriented exact dictionary matching.
  • $S_{\text{tfidf}}$: Lexical document-level cosine similarity.
  • $S_{\text{w2v}}$: Semantic concept similarity via distributed embeddings.
  • $S_{\text{bert}}$: Contextual token-level Named Entity Recognition.

2. Evaluation Metrics

Model performance is benchmarked on gold-standard holdout annotations (backend/data/annotated_skills_dataset.json) using standard Information Extraction criteria:

$$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}, \quad \text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}, \quad F_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

🔍 Engineering Tradeoffs, Limitations & Future Work

  • CPU vs. GPU Latency: DistilBERT executes in ~45 ms on CPU, compared to 1.2 ms for TF-IDF. For batch screening of thousands of resumes, asynchronous worker queues or ONNX runtime quantization would be beneficial.
  • Domain Shift: Modern software engineering frameworks evolve rapidly. An ontology-assisted hybrid approach prevents OOV failure on emerging libraries before retraining cycles.
  • Fairness & Bias Mitigation: By focusing token classification strictly on technical skill entities rather than demographic tokens, institutions, or personal names, the system prevents demographic screening bias.
